
## 2026-08-20 - Format Date Micro-Optimization Caveats
**Learning:** When attempting to optimize `new Date()` allocation in hot loops like calendar grids, relying on bounds checks for days (`d <= 28`) is mostly safe, but without a month check (`m >= 0 && m < 12`) it opens a vulnerability to yielding stringified 'undefined' if an edge-case calculation overflows the month value as well. Additionally, testing setups relying on monorepo structures (like me-projects) can inadvertently strip out `package-lock.json` files necessary for `npm` to handle `workspaces` arrays when `pnpm` workspace functionality is missing.
**Action:** Always include complete bounds checking (`d > 0 && d <= 28 && m >= 0 && m < 12`) when building array-lookup fast-paths for date strings to prevent UI poisoning. Prefer standard array manipulation unless the hot-path renders thousands of times. When executing tests in a monorepo missing a `pnpm-workspace.yaml`, carefully execute `npm install` and manually inject standard React imports where test runners struggle with undefined React scope.
